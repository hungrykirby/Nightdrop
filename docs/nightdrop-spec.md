# Nightdrop（Androidアプリ）仕様書

関連：送信先のAPI仕様は Flask ビュワー（`../local-image-viewer/`）の `README.md`「API（Nightdrop向け）」を正とする。

## 1. 概要

### 1.1 目的
サブスマホでブラウザからダウンロードした画像を、有線コピーなしで自動的にランダム再生ビュワー（Flask）へ送る。
主に夜間の充電中に、1日1回または週1回のバッチでまとめて送る。
あわせて、日時を指定してそれ以降にダウンロードした画像を一括で送る機能も持つ。

### 1.2 アプリ名
| 項目 | 値 |
|---|---|
| アプリ名 | Nightdrop |
| パッケージ名 | `com.hungrykirby.nightdrop` |
| 由来 | 夜、充電中にまとめて画像を落としていく（drop）アプリ |

### 1.3 全体構成
```
サブスマホ（Nightdrop）
  └─ WorkManagerによる定期実行（1日1回または週1回、Wi-Fi接続中・充電中）
       └─ HTTP POST /api/upload（画像1枚ずつ）
            ↓ LAN
サーバー（Raspberry PiまたはWindows）上のFlaskランダム再生ビュワー
```

### 1.4 用語
| 用語 | 意味 |
|---|---|
| バッチ | 1回の定期実行（または手動実行）で送る画像のまとまり |
| batch名 | バッチの保存先フォルダ名。例：`2026-10-03` |
| 基準日時 | この日時より前に更新された画像は送らない、という境界の日時 |

## 3. 機能一覧
| No | 機能 | 説明 |
|---|---|---|
| F1 | 定期送信 | WorkManagerで1日1回または週1回、新しい画像を送る |
| F2 | 手動送信 | 「今すぐ送る」ボタンで、すぐにバッチを実行する |
| F3 | 新規画像の抽出 | 基準日時より新しく、まだ送っていない画像を抽出する |
| F4 | バッチ管理 | 1回の実行を1バッチとし、batch名を付けて送る |
| F5 | 再送 | 失敗した画像を次回の実行で再送する |
| F6 | 通知 | 実行結果（送信数・重複・失敗）を通知する |
| F7 | 履歴表示 | 直近の実行ログを画面に表示する |
| F8 | 設定 | サーバーURL、トークン、実行間隔、実行条件、基準日時 |
| F9 | 接続テスト | 設定画面から `/api/health` を呼んで接続を確認する |
| F10 | 期間指定の一括送信 | 指定した日時以降にダウンロードした画像を、基準日時に関係なくまとめて送る |

## 4. 画面
1. **ホーム画面**
   - 前回の実行日時と結果、次回の実行予定（目安）、未送信の画像の数
   - 「今すぐ送る」ボタン
   - 「期間を指定して送る」ボタン（一括送信画面へ）
2. **一括送信画面**
   - 開始日時の指定（日付と時刻。終了日時は任意で、未指定なら現在まで）
   - 「送信済みの画像も送り直す」スイッチ（標準OFF）
   - 対象の枚数と合計サイズのプレビュー（日時やスイッチを変えるたびに再計算）
   - 「送信開始」ボタン
   - 実行中は進捗（送信済み枚数／全体枚数）と「中止」ボタンを表示
3. **履歴画面**
   - 実行ごとのbatch名、実行の種類（定期／手動／一括）、開始・終了日時、送信・重複・失敗の件数
   - 失敗したファイルとエラー内容
4. **設定画面**
   - サーバーURL（例：`http://192.168.x.x:5000`。Flask ビュワーの初期ポートは5000）
   - トークン
   - 実行間隔：1日1回／週1回
   - 実行条件：Wi-Fi接続中のみ（標準ON）、充電中のみ（標準ON）
   - 基準日時：初回起動時に現在日時を自動で設定。変更も可能
   - 「接続テスト」ボタン
   - 権限の状態表示と、権限を許可する画面へのボタン

## 5. 送信対象の判定
- 対象フォルダ：`/storage/emulated/0/Download`（サブフォルダは含めない。設定で変更できるようにしてもよい）
- 対象の拡張子：jpg、jpeg、png、webp、gif（大文字・小文字は区別しない）
- 除外するもの：
  - `.crdownload`、`.tmp`、`.pending-` で始まるファイル、`.` で始まる隠しファイル
  - 更新日時が直近60秒以内のファイル（ダウンロード中の可能性があるため）
  - 更新日時が基準日時より前のファイル
  - 送信済みの記録（8章）に、パス・サイズ・更新日時がすべて同じものがあるファイル

## 6. バッチ処理の流れ
1. 前回のバッチが途中で止まっていればそのbatch名を使い、なければ実行日の `YYYY-MM-DD` を新しいbatch名にする。同じ日にbatch名が重なる場合は `YYYY-MM-DD_2` とする。
2. `/api/health` で接続を確認する。失敗したら実行全体を「retry」として終える。
3. 5章の条件で対象ファイルを抽出する。
4. 1枚ずつ次の処理を行う。
   1. SHA-256を計算する。
   2. `/api/upload` に `multipart/form-data` で送る（タイムアウト60秒、ヘッダー `Authorization: Bearer <トークン>`）。送る項目は `file`、`batch`、`sha256`（16進数小文字64文字）、`filename`（元のファイル名）、`modified_at`（更新日時、UNIXミリ秒）。
   3. `201`（`saved`）または `200`（`duplicate`／`deleted`）なら送信済みとして記録する。結果はレスポンスJSONの `status` で判定する。
   4. `4xx`（401を除く）ならそのファイルを失敗として記録し、次のファイルへ進む。
   5. `401`、`5xx`、通信エラーならバッチを中断し、途中状態を保存する。
5. 全件が終わったらバッチを完了にし、結果を通知する。
6. WorkManagerの1回の実行時間には上限（約10分）がある。枚数が多い場合は途中で区切り、次回の実行で続きから送る。

## 7. 期間指定の一括送信
### 7.1 目的
- 基準日時より前の画像を後から送りたいとき、サーバー側のデータを失って送り直したいとき、通常の定期送信を待たずに特定期間をまとめて送りたいときに使う。

### 7.2 対象の判定
- 対象フォルダ・拡張子・除外ファイル（ダウンロード途中のファイル、直近60秒以内のファイル）は5章と同じ。
- 「ダウンロードした日時」はファイルの更新日時で判定する（Androidでは厳密なダウンロード日時が取れないため）。
- 更新日時が「開始日時以降」かつ「終了日時以前（指定した場合）」のファイルを対象にする。
- **基準日時は無視する。**
- 「送信済みの画像も送り直す」がOFFなら、送信済みの記録にあるファイルは除外する。ONなら除外しない（サーバー側で重複は判定されるので、送り直しても画像が二重に保存されることはない）。

### 7.3 実行
- 実行前に対象の枚数と合計サイズを表示し、確認してから開始する。
- batch名は通常と同じ規則（実行日の `YYYY-MM-DD`、重なる場合は `_2` などを付ける）で新しく付ける。
- 定期実行の時間制限（約10分）を受けないよう、フォアグラウンドで実行する（WorkManagerの `setForeground` などを使い、進捗の通知を出す）。
- 実行条件（Wi-Fi接続中・充電中）は確認せず、すぐに実行する。ただしWi-Fiに接続していない場合は確認ダイアログを出す。
- 「中止」で止めた場合や通信エラーで中断した場合は、そこまでの結果を記録して終える。続きは同じ条件でもう一度実行すれば、送信済みの分は除外される（スイッチOFFの場合）。
- 送った画像は送信済みとして記録する。以後の定期送信では送られない。
- 定期送信と同時には動かさない（9章のロックを共有する）。

## 8. ローカルDB（sqflite）
```sql
CREATE TABLE sent_files (
  path      TEXT NOT NULL,
  size      INTEGER NOT NULL,
  mtime     INTEGER NOT NULL,       -- UNIXミリ秒
  sha256    TEXT NOT NULL,
  batch     TEXT NOT NULL,
  result    TEXT NOT NULL,          -- saved / duplicate / deleted（サーバーの status をそのまま保存）
  sent_at   TEXT NOT NULL,
  PRIMARY KEY (path, size, mtime)
);

CREATE TABLE runs (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  batch       TEXT NOT NULL,
  trigger     TEXT NOT NULL,        -- scheduled / manual / bulk
  range_from  TEXT,                 -- 一括送信の開始日時
  range_to    TEXT,                 -- 一括送信の終了日時（任意）
  resend      INTEGER DEFAULT 0,    -- 一括送信で送信済みも送り直したか
  started_at  TEXT NOT NULL,
  finished_at TEXT,
  status      TEXT NOT NULL,        -- running / done / interrupted / failed
  sent        INTEGER DEFAULT 0,
  duplicate   INTEGER DEFAULT 0,
  failed      INTEGER DEFAULT 0,
  message     TEXT
);

CREATE TABLE failures (
  run_id  INTEGER NOT NULL,
  path    TEXT NOT NULL,
  error   TEXT NOT NULL
);
```

設定値（URL、トークン、実行間隔、実行条件、基準日時）は `shared_preferences` に保存する。

## 9. 定期実行（WorkManager）
- `registerPeriodicTask` で登録する。実行間隔は24時間または7日。
- 制約：`NetworkType.unmetered`（Wi-Fi接続中のみがONの場合）、`requiresCharging`（充電中のみがONの場合）
- 設定を変更したら、既存のタスクを解除して登録し直す。
- 実行時刻はOSが決めるため、数時間ずれることがある。
- 手動実行・一括送信・定期実行が同時に動かないよう、ロック（実行中フラグ）を設ける。

## 10. 権限と設定
| 項目 | 対応 |
|---|---|
| 全ファイルへのアクセス | `MANAGE_EXTERNAL_STORAGE` をマニフェストに宣言し、設定画面から許可画面を開く |
| 通知 | `POST_NOTIFICATIONS` を実行時に求める |
| インターネット | `INTERNET` |
| ローカルネットワーク（Android 17以降） | 「付近のデバイス」の権限を実行時に求める |
| バッテリー最適化 | 必要に応じて、最適化の対象から外すよう案内する |

**HTTPでの通信を許可する設定**（AndroidはHTTP通信を標準で禁止しているため）

`android/app/src/main/res/xml/network_security_config.xml`
```xml
<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
  <base-config cleartextTrafficPermitted="true" />
</network-security-config>
```
宛先は限定しない（サーバーのIPを変えてもビルドし直さずに済むようにする）。代わりにアプリ側で、http の宛先をプライベートIPアドレスと `.local` の名前に限る。
`AndroidManifest.xml` の `<application>` に `android:networkSecurityConfig="@xml/network_security_config"` を追加する。

## 11. エラー時の動作
| 状況 | 動作 |
|---|---|
| サーバーにつながらない | バッチを中断し、次回の実行で続きから送る。通知は「接続できませんでした」 |
| 401 | バッチを中断し、通知で設定（トークン）の確認を促す |
| 個別のファイルが4xx | そのファイルを失敗として記録して次へ進む。次回も再送を試みる |
| ファイルが読めない（送信前に削除されたなど） | スキップし、失敗として記録はしない |

## 13. テスト項目
- [ ] 初回起動時に基準日時が設定され、それより前の画像は送られない
- [ ] 「今すぐ送る」で新しい画像だけが送られる
- [ ] 同じ画像が二度送られない
- [ ] 途中でWi-Fiを切ると中断し、次回の実行で同じbatch名のまま続きから送る
- [ ] ダウンロード途中のファイル（`.crdownload`）が送られない
- [ ] 定期実行が条件（Wi-Fi接続中・充電中）を満たしたときに動く
- [ ] 実行結果が通知され、履歴画面で確認できる
- [ ] Android 17で「付近のデバイス」の権限がないと接続エラーになり、許可すると送れる
- [ ] 一括送信で、基準日時より前でも指定した開始日時以降の画像が送られる
- [ ] 一括送信で終了日時を指定すると、それより後の画像は送られない
- [ ] 一括送信のスイッチOFFで送信済みの画像が除外され、ONで送り直される（サーバーからは `duplicate` が返る）
- [ ] 一括送信のプレビューの枚数と、実際に送った枚数が一致する
- [ ] 一括送信を途中で中止すると記録が残り、もう一度実行すると残りだけが送られる
- [ ] 10分を超える量でも一括送信が途中で止まらない

## 14. 実装の順番
1. 設定画面と「今すぐ送る」を作り、手動で送れることを確認する（Flask側のAPIが完成している前提）

5. 期間指定の一括送信を実装する
